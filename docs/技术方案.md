## 1. 目标与范围

### 1.1 业务目标
1. **认证准入**：用户必须先完成身份认证，才能浏览核心内容和购买课程。
2. **双身份分流**：医生和从业者走不同的首页、内容和运营路径。
3. **课程交易**：在线课程（免费、试看、付费）和线下课（定金加尾款），都在小程序内完成下单和支付。
4. **从业者招商**：做招商页和留资表单，留资数据进入后台跟进。

## 2. 总体架构

```
┌──────────────────────────┐     ┌──────────────────────────┐
│  微信小程序（用户端）       │     │  管理后台（Web，运营端）    │
│  uni-app · Vue3 · TS       │     │  Vue3 · Element Plus · TS │
└────────────┬─────────────┘     └────────────┬─────────────┘
             │ HTTPS（已备案域名）              │ HTTPS
             ▼                                ▼
┌─────────────────────────────────────────────────────────┐
│                 Nginx（TLS 终止 / 反向代理 / 限流）          │
└────────────────────────────┬────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────┐
│            业务后端 API（NestJS · TypeScript · Prisma）      │
│  auth │ user/cert │ course │ media │ order/pay │ lead │ admin │
└───────┬───────────────┬───────────────┬─────────────────┘
        ▼               ▼               ▼
   MySQL 8.0        Redis 7        定时任务 / 队列（BullMQ）
 （主业务库）   （会话/限流/缓存）  （订单超时关单、对账、通知）
        │
        └── 外部服务 ───────────────────────────────────────
            · 微信开放接口（code2Session、订阅消息、手机号）
            · 微信支付 V3（JSAPI 下单 / 回调 / 退款 / 对账）
            · 腾讯云 COS（证件私有桶 + 公共资源桶 + CDN）
            · 腾讯云 VOD 云点播（转码 / 加密 / 播放签名 / 防盗链）
            · 腾讯云 SMS（可选：审核结果、线下课提醒）
```

**设计原则**
- **独立自建**：业务数据、用户和订单全部在客户自己的云账号里，不依赖第三方 SaaS 作为核心载体。
- **模块化单体**：一期用单体应用，内部按领域划分模块。体量小、交付快、易运维；模块边界清楚，以后需要时可以拆分。
- **二期可扩展**：数据模型为分销、题库、积分预留扩展字段和事件钩子，比如订单完成事件，一期不实现相关逻辑。

## 3. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 小程序端 | **uni-app（Vue 3 + TypeScript + Vite）** + Pinia + uView Plus / Wot Design | 组件生态成熟，开发效率高；以后要扩展 H5 或 App 时可以复用 |
| 管理后台 | **Vue 3 + Element Plus + TypeScript**（基于 vue-pure-admin 或同类模板） | 自带权限路由和表格表单，适合轻量运营后台 |
| 后端 | **Node.js 20 LTS + NestJS 10 + Prisma** | 前后端统一用 TS，类型可以共享；NestJS 的模块、守卫、拦截器适合做鉴权和审计 |
| 数据库 | **MySQL 8.0**（腾讯云 TencentDB） | 国内云托管成熟，有自动备份 |
| 缓存/队列 | **Redis 7** + BullMQ | 会话、限流、幂等锁、订单超时关单延迟任务 |
| 对象存储 | **腾讯云 COS**（私有桶 + 公共桶）+ CDN | 证件放私有桶，课程封面和图文素材放公共桶 |
| 视频点播 | **腾讯云 VOD** + 超级播放器签名（psign） | 有转码、HLS 加密、Key 防盗链、播放鉴权，与 COS 同生态 |
| 支付 | **微信支付 API V3**（JSAPI / 小程序支付） | 小程序唯一可用的支付通道 |
| 部署 | Docker Compose · 腾讯云 CVM / 轻量服务器 · Nginx | 一期规模足够，运维简单 |
| CI/CD | GitHub Actions：lint、测试、镜像构建；小程序用 miniprogram-ci 上传体验版 | 自动化交付 |
| 监控 | 腾讯云云监控 + 应用日志（pino → CLS）+ 告警 | 告警到企业微信或飞书 |

> 最终框架在 WP01（需求冻结）阶段与客户确认后冻结，对应报价单中的“具体前端框架在技术方案确认时冻结”。

## 4. 核心模块设计

### 4.1 登录与认证准入（WP03）

**登录**
1. 小程序调用 `wx.login` 拿到 code，后端用 `code2Session` 换取 `openid / unionid`，签发 JWT：access 2 小时，refresh 30 天，存在 Redis 里，可以吊销。
2. 用户授权手机号（`getPhoneNumber`），后端解密后加密存储。

**身份认证状态机**
```
UNSUBMITTED ──提交资料──▶ PENDING ──审核通过──▶ APPROVED
                              │
                              └──驳回(附原因)──▶ REJECTED ──重新提交──▶ PENDING
APPROVED ──后台撤销──▶ REVOKED
```
- 身份分两类：`DOCTOR`（医生）和 `PRACTITIONER`（从业者）。每类证件字段可以在后台配置，比如医师执业证、工作证明、营业执照。
- **准入拦截**：后端的 `CertGuard` 会拦截核心内容和下单接口，未认证用户只能访问登录、认证、招商和公开介绍页。小程序端用路由守卫配合空态引导页。
- 审核结果通过**订阅消息**通知用户，短信可选。
- 一期只做人工审核。证件上传接口预留 `ocrResult` 字段，二期接 OCR 时不改表结构。

**敏感信息保护**
- 证件图片放 COS **私有桶**，后台审核时用 5 分钟有效的临时签名 URL 查看，前端不落地缓存。
- 证件号、手机号等字段在应用层用 **AES-256-GCM** 加密存储，密钥由环境变量或 KMS 管理；另存哈希列用于去重和检索。
- 只收集审核必需的字段（最小化）。审核员查看证件的操作写入审计日志。
- 小程序要配置《用户隐私保护指引》，首次收集信息时弹窗取得授权。

### 4.2 课程内容体系（WP04）

**模型层级**
```
分类 Category（二级：一级分类 → 二级分类，例如“产品系列 / 专题回放”）
  └─ 课程产品 Product（类型：COURSE 单课 / COLUMN 专栏 / SERIES 系列）
       └─ 章节 Chapter
            └─ 课时 Lesson（类型：VIDEO / AUDIO / ARTICLE）
```
- **定价模式**：`FREE` / `PAID`。课时可以单独标记“可试看”，并设置试看时长（秒）。
- **身份可见性**：每个产品可配置 `visibleTo = [DOCTOR, PRACTITIONER]`，实现双身份差异化内容。
- **线下课**作为独立产品类型 `OFFLINE`，带场次、地点、名额、定金和尾款金额。
- 图文详情用富文本（后台编辑器，图片上传到 COS 公共桶并走 CDN）。

### 4.3 视频点播、音频与学习进度（WP05）

**视频**
- 运营在后台上传视频，用 VOD 客户端直传，不经过业务服务器。上传后触发转码任务模板：多码率自适应 HLS 加 **私有加密（SimpleAES / 私有协议）**。
- **播放鉴权**：小程序请求 `/media/:lessonId/play-sign`，后端校验“已认证 + 已购买或免费 + 身份可见”，再签发短时效（例如 2 小时）的播放签名 psign。
- **防盗链**：开启 VOD Key 防盗链（URL 带时间戳签名）和 Referer 白名单。
- **试看**：对未购买用户，签发试看限制的播放凭证，或播放转码生成的独立试看片段。具体按 VOD 当期能力确定，前端同时做到点暂停加购买引导。
- **防录屏**：叠加用户昵称和 ID 尾号的**动态浮动水印**，用于追溯。按报价单约定，**不承诺完全阻止外部设备录制**。

**音频（每日 60 秒）**
- 短音频按日期发布，形成音频栏目，可以设为免费或认证可见。用 `wx.getBackgroundAudioManager` 实现后台播放。

**学习进度**
- 前端每 15 秒以及暂停、退出时上报 `lessonId + position + duration`，后端写 Redis，再异步批量落库，避免高频写 MySQL。
- 规则：观看达到 90% 记为完成。课程进度 = 已完成课时数 / 课时总数。

### 4.4 交易、订单与支付（WP06）

**订单状态机**
```
CREATED(待支付) ──支付成功回调──▶ PAID ──▶（自动开通权益）
    │                              │
    ├──超时 30 分钟未付──▶ CLOSED    └──后台退款──▶ REFUNDING ──▶ REFUNDED
    └──用户取消──▶ CANCELLED
```

**线下课（定金加尾款）**：一个报名单 `Enrollment` 关联两张订单
```
DEPOSIT_PENDING ──付定金──▶ DEPOSIT_PAID ──付尾款──▶ COMPLETED
                                 └──逾期 / 取消──▶ CANCELLED（定金规则按后台配置）
```

**关键实现**
- 微信支付 **API V3**：JSAPI 下单、回调验签和 AES 解密、查单、退款、每日对账单下载（定时任务）。
- **幂等**：回调按 `out_trade_no` 加 Redis 分布式锁，并校验订单状态；权益开通放在同一个事务里。
- **金额安全**：价格和优惠全部在服务端计算，前端只传商品 ID 和优惠券 ID；金额统一用“分”（整数）存储。
- **超时关单**：用 BullMQ 延迟任务，并调用微信关单接口。
- **优惠（基础版）**：
  - 早鸟价、限时价：作为产品上的价格策略（时间窗加价格），系统自动取当前生效价。
  - 优惠券：满减或立减，有有效期和适用范围（全部 / 指定分类 / 指定产品），后台发放或用户领取，每单限用一张。

**平台规则（重要风险，详见第 9 节）**
- 支付需要客户先完成：商户号入驻 → 小程序开通支付权限 → 商户号与 AppID 绑定。
- 小程序销售**虚拟课程**时，iOS 端受平台虚拟支付政策约束。技术上预留按平台识别的开关（`platform === 'ios'` 时的购买策略可在后台配置），最终方案以客户主体资质、类目和平台审核结果为准。

### 4.5 学习中心（WP07）
- “我的课程”：已购和已领取的免费课程列表，显示最近学习的课程和续播位置。
- “学习进度”：课程维度的完成度、累计学习时长。
- “我的订单”和“我的报名”：线下课状态及尾款支付入口。

### 4.6 从业者招商（WP08）
- 招商页由后台配置的区块化内容组成（Banner、权益介绍、案例、FAQ），可以迭代，最多 2 版设计。
- **留资表单**：姓名、手机号、城市、机构名称、意向等，字段可配置。提交时有频率限制（同一 openid 或手机号每天 N 次）和必要的校验。
- 留资进入后台“线索”列表，可标记跟进状态并导出 Excel。可选：新留资时推送企业微信或飞书机器人通知。

### 4.7 管理后台（WP09）
| 菜单 | 功能 |
|---|---|
| 工作台 | 待审核认证数、今日订单、今日留资（简单统计，不是二期的数据看板） |
| 内容管理 | 分类、课程、专栏、系列、章节、课时、音频、视频上传、富文本、课程评价 |
| 用户与认证 | 用户列表、认证审核（通过 / 驳回附原因）、撤销认证 |
| 订单 | 订单、线下课报名、退款、对账结果 |
| 营销 | 价格策略、优惠券 |
| 运营配置 | Banner、首页推荐位（按身份分别配置）、招商页内容 |
| 线索 | 招商留资 |
| 系统 | 管理员账号、角色权限（RBAC：超管 / 运营 / 审核员 / 财务）、操作日志 |

定位为**轻量运营后台**，不做 CRM 或 CDP（与报价单一致）。

### 4.8 课程评价（一期新增，轻量版）
参照客户现在小鹅通课程页的「评价」区，做一个只针对已购学员的轻量版：
- **谁能评**：已购学员（含通过专栏 / 系列获得的课程）；线下课已付定金或已结业的学员。免费课程不开放评价。
- **怎么评**：1~5 星 + 5~500 字文字，可选匿名（显示「匿名用户」，否则显示昵称首字 + `**`）。每人每门课一条，可修改；修改后重新走内容检测，并取消精选。
- **展示**：课程详情页显示评价数、平均分和前 3 条，「查看全部」进入评价列表；精选在前，其余按时间倒序。官方回复显示在评价下方。
- **内容安全**：提交时调用微信 `msgSecCheck`（v2）。检测通过直接展示；建议人工复核或接口异常时进入「待审核」，后台确认后展示；判定违规直接拒绝提交。
- **后台**：「内容 → 课程评价」按状态 / 评分 / 课程筛选，可展示、隐藏、精选、回复，操作记审计日志。
- **不做**：图片 / 视频评价、点赞、学员之间互相回复、评价送积分或优惠券（如需要放二期）。

## 6. 接口设计约定

- RESTful 风格，前缀 `/api/v1`（小程序端）和 `/admin/v1`（后台）；OpenAPI（Swagger）自动生成文档。
- 统一响应：`{ code, message, data, traceId }`；分页：`{ list, total, page, pageSize }`。
- 鉴权：小程序用 JWT 加 `CertGuard`（认证准入），后台用 JWT 加 RBAC 权限点。
- 关键接口示例：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/auth/wx-login` | code 换 token |
| POST | `/api/v1/cert/upload-sign` | 获取证件直传 COS 的临时凭证 |
| POST | `/api/v1/cert/submit` | 提交认证 |
| GET | `/api/v1/home?identity=` | 按身份返回首页配置 |
| GET | `/api/v1/products` / `/products/:id` | 课程列表和详情 |
| GET | `/api/v1/lessons/:id/play-sign` | 播放签名（鉴权、试看） |

## 7. 安全与合规

| 方面 | 措施 |
|---|---|
| 传输 | 全站 HTTPS（TLS 1.2+），小程序后台配置合法请求域名 |
| 数据 | 敏感字段 AES-GCM 加密加哈希检索；证件放私有桶；数据库只开内网访问，每天自动备份并保留 7 天以上 |
| 接口 | 限流（按 IP 和用户），关键写操作防重放和幂等；参数校验用 class-validator |
| 后台 | 账号密码加图形验证码，登录失败锁定；RBAC；全量操作审计 |
| 内容 | 课程评价提交时调用微信内容安全接口 `msgSecCheck`，疑似违规进入人工审核；以后如有图片类用户内容再接 `mediaCheckAsync` |
| 隐私 | 《用户协议》《隐私政策》，小程序隐私保护指引；遵循《个人信息保护法》最小必要原则 |
| 备案与资质 | 小程序备案、后端域名 ICP 备案（小程序合法域名必须是已备案域名）；教育和医疗健康相关类目资质由客户负责，我方协助整理 |

## 9. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| **iOS 虚拟商品支付政策** | iOS 端可能无法直接购买在线课程 | WP01 阶段确认客户主体、类目和平台当期政策；技术上做平台开关和合规引导；线下课属于实物或服务，不受影响 |
| 支付权限或商户号开通延迟 | WP06 联调受阻 | WP01 就提醒客户启动申请；先用模拟支付把订单流程跑通 |
| 医疗健康类内容审核 | 类目或审核被拒 | 客户提前准备类目资质；课程内容的医学合规由客户审核（报价单已约定） |
| 备案周期 | 影响上线时间 | 第一周就提交小程序和域名备案；审核期不计入工期 |
| 视频被录屏传播 | 内容外流 | 加密、鉴权、防盗链加动态水印，提高门槛并可追溯；合同已注明不能完全杜绝 |
| 需求蔓延 | 工期失控 | D5 冻结需求并签字；新增需求走变更流程，另行评估 |
